#+TITLE: Features and Setup Notes
This document records what is configured in =init.el=, the key bindings,
and the reasoning / verification behind the less obvious setup. It is a
companion to the inline comments in =init.el= and the operational notes in
=../README.org=.

Standard keys (=C-x b=, =C-s=, =M-y=, =M-g g=) are intentionally left intact;
new features are bound to free keys so the two can be compared.

*xref navigation note:* =M-.= (=xref-find-definitions=) works, but =M-,= does
not reach this GUI Emacs (Option+comma is swallowed below Emacs) and =M-?= is
rebound to =help-command=. So =xref-go-back= is on =C-c ,= and
=xref-find-references= on =C-c r=.

* Completion and LSP
Two independent completion layers, by design:
- *Minibuffer* -- vertico + orderless + marginalia + consult (for =M-x=,
  find-file, buffer switching, search commands).
- *In-buffer* -- corfu shows a popup at point for =completion-at-point=,
  including eglot's LSP candidates. It pops up automatically while typing.

=eglot= (built-in) auto-starts a language server (=eglot-ensure=) in =c-mode= /
=c++-mode= (clangd) and =rust-ts-mode= (rust-analyzer). It wires the standard
Emacs facilities: eldoc (hover), flymake (diagnostics), xref
(definitions/references), and =completion-at-point= (shown by corfu). clangd
reads =compile_commands.json=; servers are found via PATH (exec-path-from-shell)
or the project's flake (envrc).

Rust uses the built-in =rust-ts-mode= (tree-sitter). Its grammar is not shipped
with Emacs, so =init.el= registers the grammar source and installs it once if
missing (only under a window system, so the batch health-check stays offline).
The compiled grammar lands in =tree-sitter/= (gitignored). If a =.rs= buffer
is not fontified, run =M-x treesit-install-language-grammar= for =rust=.

Diagnostics navigation: modern flymake ships no default keys and =M-g n= /
=M-g p= (next-error) are not wired to flymake, so they are bound explicitly
under the classic =C-c != prefix: =C-c ! n= next, =C-c ! p= previous, =C-c ! l=
list buffer diagnostics.

Buffer-word completion: the built-in =dabbrev= (=M-/=) completes the word at
point from buffer contents. To also get buffer words in the corfu popup,
=cape= registers =cape-dabbrev= (buffer words) and =cape-file= (file paths) on
the global =completion-at-point-functions=. These show up in ordinary buffers;
in eglot (LSP) buffers eglot installs its own buffer-local capf, so LSP
completion stays primary there (merging buffer words into LSP buffers with
=cape-capf-super= is deferred).

* Per-directory environments (nix flake + direnv)
This machine uses =direnv= + =nix-direnv= with a =.envrc= (=use flake=) per
project directory. Two independent paths make those environments work inside
Emacs:

- *Inside vterm* -- vterm runs =$SHELL= (zsh), whose direnv hook loads the
  directory's =.envrc= automatically. Nothing Emacs-specific is needed.
- *Emacs-native commands* (=compile=, =eglot=, executable lookup) -- these do
  not go through the shell, so =envrc= applies the =.envrc= environment
  buffer-locally instead. This is what feeds the flake toolchain (e.g. clangd)
  to eglot -- see the Completion and LSP section.

Prerequisite: a GUI Emacs on macOS starts with a minimal PATH and cannot see
=direnv= / =nix=. =exec-path-from-shell= imports the login shell's PATH so
=envrc= can find =direnv=.

*Gotcha:* a new or changed =.envrc= must be approved once with =C-c e a=
(=envrc-allow=) before Emacs will apply it.

** Verified working (2026-07-28)
- =envrc= applies a directory's =.envrc= to Emacs buffers (checked that a
  project's flake variables appear via the minibuffer, e.g. =M-: (getenv ...)=).
- =vterm= runs a full terminal inside Emacs -- Neovim launches inside it and
  its LSP works, confirming vterm is a real PTY.
- =vterm='s native module builds via cmake/libtool and is pre-compiled.

* Background transparency (deferred)
Matching kitty's =background_opacity 0.90= was attempted but dropped: on
macOS Tahoe (26) the built-in =alpha-background= is not rendered even under
emacs-plus (no transparency even at 50). The tokyo-night theme is kept. To
revisit, use the emacs-plus =window-blur= community patch (blur + configurable
alpha) or the =emacs-liquid-glass= package (needs emacs-plus@31). See the
comment near the theme block in =init.el=.

* Helper scripts
See =../scripts/=:
- =health-check.sh= -- load =init.el= under batch Emacs (=--refresh= updates
  stale MELPA archives).
- =package-search.sh REGEXP= -- search available packages by name/summary.
- =emacs-eval.sh [--install PKG] 'ELISP'= -- evaluate Elisp in a batch Emacs
  with the archives ready (probe packages/themes); add =--init= to load the
  full config first and probe the live state (key bindings, capf, ...).
