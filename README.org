#+TITLE: Emacs Config
This is my personal Emacs configuration repository. In this file, I
write operational notes, tips, and so on, to my future self.

See [[file:docs/features.org][docs/features.org]] for the installed features,
key bindings, and the direnv / vterm setup.

* Conventions
+ Commit messages follow [[https://www.conventionalcommits.org/][Conventional Commits]]:
  =type(scope): summary= (e.g. =feat(completion): add vertico=,
  =chore(scripts): ...=, =docs: ...=). One commit per feature.
+ Code comments in =init.el= are written in English.
+ Batch Emacs runs (=emacs --batch=) go through a script in =scripts/=,
  not ad-hoc one-off commands. Existing helpers: =health-check.sh= (load
  the config), =package-search.sh= (find packages), =emacs-eval.sh= (probe
  packages, or =--init= to probe the live config: key bindings, capf, ...).
  If none fits the task, add a new script rather than running a one-off.

* Health check
Load the whole config in a throwaway batch session; a non-zero exit
means initialization raised an error.
#+BEGIN_SRC sh
  cd ~/.emacs.d && emacs --batch -l init.el
  echo $?
#+END_SRC

This is wrapped in a script for convenience:
#+BEGIN_SRC sh
  scripts/health-check.sh            # load init.el, report pass/fail
  scripts/health-check.sh --refresh  # refresh package archives first
#+END_SRC

Use =--refresh= when a package install fails with =file-error ...
Not found=: MELPA drops old tarballs daily, so a stale local archive
can point at versions that no longer exist on the server.

Claude calls it internally in =/elisp-review=.

* Finding packages
Search the configured archives by name or summary (case-insensitive):
#+BEGIN_SRC sh
  scripts/package-search.sh tokyo   # e.g. find Tokyo Night themes
#+END_SRC
Refresh first (=scripts/health-check.sh --refresh=) if results look stale.

Inspect anything else (themes a package provides, key bindings, ...) by
evaluating Elisp in a batch Emacs with the archives ready:
#+BEGIN_SRC sh
  scripts/emacs-eval.sh '(princ (emacs-version))'
  scripts/emacs-eval.sh --install tokyo-night \
    "(dolist (th (custom-available-themes)) (princ (format \"%s\\n\" th)))"
#+END_SRC

* Debugging

To catch initialization errors, run Emacs with following option:
#+BEGIN_SRC sh
  emacs --debug-init
#+END_SRC

To run Emacs on isolated environment, run it:
#+BEGIN_SRC sh
  emacs -Q
#+END_SRC
or
#+BEGIN_SRC sh
  emacs --init-directory <dir>
#+END_SRC

+ =M-x toggle-debug-on-error=, =*Messages*=, =*Warnings*=.
+ =M-x check-parens=, comment out splitting.
+ =M-:= query the live Emacs.
+ Write test script using =emacs --batch --eval=.
* Reload
Emacs reads =init.el= once, at startup; editing the file does not touch
the running session until the new code is evaluated. Two built-in tools
cover this, picked by how much changed:

+ *One form* -- put point inside the edited =(use-package ...)= (or any
  top-level form) and press =C-M-x= (=eval-defun=). Only that form
  re-runs, so it is always safe. This is the day-to-day motion.
+ *Everything / when in doubt* -- =M-x restart-emacs= reloads the whole
  config in a pristine session.

Re-evaluating the /entire/ =init.el= in place (=eval-buffer=) is
deliberately avoided: re-evaluation is not idempotent in general
(duplicated hooks, toggled modes, re-run side effects), so it becomes a
latent footgun as the config grows. Prefer per-form =C-M-x=, or a clean
=restart-emacs=.
